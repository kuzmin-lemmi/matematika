## 1. Что это за проект

Сайт с интерактивными материалами для учителей математики 5–9 классов:
- 5–6 класс — математика по учебнику **Виленкина**;
- 7–9 класс — алгебра по учебнику **Макарычева** и геометрия по учебнику **Мерзляка**.

Главное условие: **у математика нет компьютерного класса.** В классе один экран (доска или проектор) и тетради,
телефоны ученикам на уроке использовать нельзя. Поэтому каждый материал — это одна тема в трёх режимах:

| Режим | Где | Что делает |
|---|---|---|
| 🖥 **На доске** | урок, проектор или интерактивная доска | пошаговый живой чертёж или показ, учитель ведёт, класс отвечает |
| 🖨 **Раздатка** | урок, бумага | генератор вариантов: у каждого свой, ключ учителю по номеру варианта |
| 🏠 **Дома** | телефон или компьютер ученика | тренажёр по ссылке из чата класса, с разбором каждой ошибки |

Все три режима работают на одном генераторе заданий. Это то же ядро, что у соседнего проекта автора «Инфошаг»
(игры по информатике, github.com/kuzmin-lemmi/personal_ebsite): генерация, ловушки на типичных ошибках, разбор.

Пока проект — **только статический сайт**. Не добавляй сервер, базу данных, авторизацию, платежи
или сторонние сервисы без прямой просьбы автора (см. раздел 9). Домашние задания с журналом — это
отдельный этап с сервером, план в `docs/HOMEWORK.md`.

**Адреса не ломаем.** Наружу (посты, раздатки, чат класса, письма) уходят только адреса страниц
(`/item/<slug>/`, `/zapusk/<slug>/`), не прямые ссылки на файлы материалов. Slug после публикации не меняется.
Подробно — `docs/SITE.md`.

## 2. Стек и команды

- [Astro](https://astro.build) 7, TypeScript, без UI-фреймворков (React/Vue не подключать).
- Контент — Markdown-файлы с frontmatter в коллекции `items`.
- Публикация — GitHub Pages через `.github/workflows/deploy.yml` (пока запуск вручную, см. `docs/ROADMAP.md`).

```bash
npm install
npm run dev       # http://localhost:4321/
npm run build     # обязательно перед завершением задачи — сборка должна пройти без ошибок
npm run preview
npm run posters <slug>   # картинка-превью материала (нужен Chrome или Edge)
```

Адрес сайта задаётся в `astro.config.mjs` (`site`, `base`). Сейчас — `https://matshag.ru`, `base: '/'`.
**Все внутренние ссылки строй через `import.meta.env.BASE_URL`** или функции из `src/lib.ts`
(`openPageHref`, `pageHref`, `openHref`). Кнопка открытия материала — всегда `openPageHref` (ведёт на `/zapusk/<slug>/`).
Ссылки вида `href="/catalog"` сломаются на GitHub Pages.

## 4. Как добавить материал (самая частая задача)

**Новые материалы делаются в конструкторе** — `D:\Конструктор математика` (отдельная папка, не в этом репозитории).
Он собирает материал из общего ядра и темы в один файл `public/materials/<slug>.html`. Как им пользоваться —
`ИНСТРУКЦИЯ.md` конструктора; порядок работы для ИИ — навык `D:\Конструктор математика\.claude\skills\novyi-material\SKILL.md`.
Заготовка — `npm run new -- <slug> --title "…"` в папке конструктора: она создаёт тему, карточку (шаг 2) и черновик теста.
Проверка — `npm run check -- <slug>`, показ автору — `npm run show -- <slug>`, публикация одобренного автором
материала — `npm run publish -- <slug> --approved` (только после явного «одобряю» в чате; коммит, PR, слияние,
GitHub Pages и проверка matshag.ru — внутри команды).

Файлы, собранные конструктором, начинаются с комментария «Собрано конструктором» — **руками их не правь**:
правь тему или ядро в конструкторе и пересобирай (`npm run build -- <slug>`). Сейчас так собран
`arifmeticheskii-kvadratnyi-koren`; «Сложение дробей» и «Углы» пока отдельные файлы — их правят как раньше.

Без конструктора (только если он недоступен):

1. Скопируй `templates/material.html` в `public/materials/<slug>.html` и замени всё, что помечено «ЗАМЕНИ». Slug — латиница через дефис, транслит названия
   (`slozhenie-drobei`, `ugly-pri-parallelnyh-pryamyh`).
2. Создай или обнови `src/content/items/<slug>.md`:

```markdown
---
title: Сложение дробей с разными знаменателями
type: lesson                  # lesson | course | app
subject: math                 # math (5–6, Виленкин) | algebra (Макарычев) | geometry (Мерзляк)
parts: [board, print, home]   # какие режимы есть в материале
sheets:                       # необязательно: другие виды листа раздатки — отдельная кнопка на сайте
  - { kind: oge, label: "Бланк ОГЭ" }   # ведёт на /zapusk/<slug>/?mode=print&kind=oge; материал читает ?kind=
summary: "Одно-два предложения для карточки"
emoji: 🍰
color: "#E07A1F"              # основной цвет материала, им красится обложка карточки
url: materials/slozhenie-drobei.html   # без ведущего слеша; внешние — полным адресом https://…
access: free                  # free | paid | external | soon (soon — карточка без кнопок, страница с noindex)
grades: [6]
topic: "Сложение и вычитание дробей с разными знаменателями"
textbook: "Виленкин и др. Математика, 6 класс — сложение и вычитание дробей"   # без номеров параграфов, если их не дал автор
duration: "5–10 минут на доске"
tags: [обыкновенные дроби, НОК]
order: 220                    # 5 класс — 100–199, 6 — 200–299, 7 — 300–399, 8 — 400–499, 9 — 500–599, курсы — 900+
added: 2026-11-01             # дата публикации; самый свежий материал показывается в блоке «Новое»
poster: posts/slozhenie-drobei.jpg   # картинка из режима доски (npm run posters)
---
Описание материала — обычный Markdown, по абзацу на каждый режим: «**На доске.** …», «**Раздатка.** …», «**Дома.** …».
```

3. Сними картинку-превью: `npm run posters <slug>` — скрипт откроет материал с `?mode=board&preview=1`
   и сохранит `public/posts/<slug>.jpg` и `<slug>-dark.jpg`. Кадр выбирает сам материал (`APP.board.poster()`,
   в конструкторе — `BOARD.poster`); вписывать материал в скрипт не нужно. Пропиши `poster` в карточке.
4. Строковые значения с двоеточием, кавычками или тире в начале **бери в кавычки** — иначе YAML не разберётся.
5. Запусти `npm run build` и убедись, что появились страницы `/item/<slug>/` и `/zapusk/<slug>/`.

Нужно новое поле? Сначала добавь его в `src/content.config.ts` (с `.optional()` или `.default()`,
чтобы старые карточки не сломались), потом выводи в шаблонах.

## 5. Правила для самих материалов (`public/materials/*.html`)

Подробный стандарт режимов — `docs/FORMATS.md`, техника — `docs/TECH.md`. Здесь — обязательный минимум.

**Файл**
- Один самодостаточный HTML: CSS и JS внутри файла. Никаких сборщиков, npm-пакетов, модулей и библиотек
  (KaTeX, MathJax, JSXGraph, GeoGebra тоже нельзя: дроби и чертежи рисуем сами — CSS и SVG).
- Внешние ресурсы — только шрифты Google Fonts с запасными шрифтами в `font-family`.
- Картинки — inline SVG или data-URI. Никаких запросов к другим сайтам: материал должен работать
  в школьной сети с фильтрами и открытым с флешки.
- `localStorage` только для удобств (рекорд, настройки) и **всегда в `try/catch`** — без него материал обязан работать.

**Адрес материала**
- `?mode=board | print | home` — сразу открыть режим, без стартового экрана.
- `?preview=1` — превью на сайте: без звука, без захвата фокуса, режим доски сам показывает движение
  (например, крутит секущую). По нему же снимается картинка `npm run posters`.
- `?student=1` — ссылка для учеников: только тренажёр, без меню и выхода к доске и раздатке (константа `STUDENT`).
- Без параметров — стартовый экран с выбором режима: «🖥 На доске», «🖨 Раздатка», «🏠 Тренировка».

**Интерфейс**
- Весь текст — по-русски, обращение к ученику на «ты».
- Читаемость на проекторе: крупные цифры и кнопки, высокий контраст, на доске — шрифт не мельче 28px.
- Цвета — переменными в `:root`, тёмная тема через `prefers-color-scheme`; раздатка печатается всегда чёрным по белому.
- `<meta name="viewport" ... viewport-fit=cover>` и отступы `env(safe-area-inset-*)`.
- Управление и мышью/касанием (интерактивная доска), и с клавиатуры. Esc — пауза или выход в меню.
  На доске «Далее» — `→`, `Пробел`, `PageDown` (пульты для презентаций шлют PageDown/PageUp), «Назад» — `←`, `PageUp`.
- `prefers-reduced-motion` — отключать лишнюю анимацию.

**Математическая запись** (подробно — `docs/TECH.md`)
- Десятичная запятая: `2,5`, не `2.5`. Ввод ответа принимает и запятую, и точку.
- Минус — `−` (U+2212), умножение — `·`, деление в 5–6 классе — `:`. Переменные — курсивом.
- Обыкновенные дроби — «этажом» (числитель над знаменателем), смешанные числа — как в учебнике.
- Обозначения и термины — как в учебнике класса: `∠ABC`, `△ABC`, `a ∥ b`, `AB ⊥ CD`, градусы `°`.

**Обязательные части каркаса**
- Все параметры — в объекте `CONFIG` в начале скрипта (число заданий и вариантов, уровни, баллы, штраф за подсказку,
  пороги оценок), чтобы учитель мог поменять их за минуту.
- **На доске:** шаги по кнопке «Далее», у шага — вопрос классу до показа ответа; учитель задаёт темп, таймер — только
  там, где он часть упражнения (устный счёт).
- **Раздатка:** номер варианта = зерно генератора; по номеру собираются и задания, и ответы; лист ученика, ключ
  учителя, таблица ответов внизу листа; печать A4 из браузера (`@media print`).
- **Дома (тренажёр):** настройки, очки, серия, рекорд; подсказки по шагам (со штрафом); новое задание с другими
  числами после ошибки; экран итогов с блоком «Над чем поработать» по типам ошибок; справка с теорией по теме.
- Каждая ошибка **объясняется**: не «неверно», а почему и как правильно, с вычислением.
  Если ошибка типичная — называем её: «Ты сложил числители и знаменатели: так дроби не складывают».

**Методика**
- Опирайся на учебник класса (Виленкин / Макарычев / Мерзляк), а для 8–9 классов держи в уме ОГЭ.
- Не вводи ошибочных упрощений и неверных «правил-подсказок».
- Задания генерируются, а не берутся из фиксированного списка, и отсекают вырожденные случаи: одинаковые
  варианты, ответ виден без вычислений, «случайно» целый ответ там, где тренируется дробный, прямой угол там,
  где он делает задачу тривиальной.
- Варианты-ловушки строй на типичных ошибках учеников (список по темам — `docs/MATERIALS.md`), а не случайно.

**Проверка материала** — перед сдачей прогони автотест в Node + `jsdom` (тесты — в `tests/`, не в `public/`):
- тренажёр: программно реши по 20–40 заданий каждого типа и уровня через функции материала, проверь,
  что каждое доходит до состояния «решено», а неверный ответ даёт объяснение;
- раздатка: сгенерируй 30 вариантов — все различны, один номер всегда даёт один и тот же вариант,
  ключ совпадает с ответами, посчитанными в тесте независимо;
- доска: пройди все шаги вперёд и назад без ошибок в консоли.
jsdom не считает раскладку (`getBBox`, размеры — нули): геометрию проверяй по координатам из модели, а не из DOM.

После добавления или изменения материала обнови его карточку в `src/content/items/`.

**Большие материалы и общий каркас.** Каркас материала (экраны, доска, раздатка, бланк ОГЭ, тренажёр) живёт в ядре
конструктора `D:\Конструктор математика`, тема — отдельно; сборка даёт один файл `public/materials/<slug>.html`.
Тест-контракт конструктора проверяет каждую тему одинаково, тест темы на сайте — независимое решение.
Готовый файл подчиняется всем правилам выше.

**Чужие миры и персонажи.** Не используем узнаваемых персонажей, названия и образы из книг, фильмов,
мультфильмов и игр (даже «в честь»). Вдохновение жанром — можно, заимствования — нельзя.

## 6. Стиль кода

- TypeScript в `.astro` и `.ts`; в материалах — современный JS без библиотек.
- Имена переменных и функций — по-английски, комментарии — по-русски и только там, где неочевидно.
- Не переформатируй файлы целиком и не переименовывай без нужды — дифф должен показывать суть правки.
- Стили компонентов — в `<style>` внутри компонента; общие токены — только в `global.css`.
- Не добавляй зависимости без необходимости. Новая зависимость — объясни в ответе зачем.
  Для тестов допустимы dev-зависимости (`jsdom`).

## 7. Тексты на сайте

- Пишем для учителя математики: коротко, по делу, без маркетинговых штампов.
- Описание — только про сам материал, по абзацу на режим; раздел «Как использовать на уроке» не пишем.
- Не выдумывай факты об авторе, номера параграфов, страницы учебника и цены — если не знаешь, оставь поле пустым
  и скажи об этом в ответе. Содержание учебников по главам сверяй у автора: издания отличаются.

## 8. Перед тем как сказать «готово»

- [ ] `npm run build` проходит без ошибок и предупреждений о контенте
- [ ] новые страницы открываются через `npm run preview` с учётом `base`
- [ ] нет абсолютных внутренних ссылок без `BASE_URL`
- [ ] для материалов — автотест пройден, раздатка проверена в предпросмотре печати, карточка обновлена
- [ ] в ответе перечислено, какие файлы изменены и что проверить руками

## 9. Решения, которые принимает только автор

Спроси, прежде чем делать:
- серверная часть, база данных, авторизация, личные кабинеты, домашние задания с журналом;
- платежи и всё, что связано с деньгами и чеками;
